#Findings and fixes

FindingRiskFix
-i was advertised but not parsed as a short flagThe new interactive wizard was documented but inconvenient/broken for the advertised shorthandbin/lehrosol.js parser now supports short flags (-i, -q, -h, -v)
--dryRun=false was advertised but parsed as a string or ignored when passed as --key=valueUsers could think they were running a real adapter while still dry-runningParser now supports --key=value and coerces true / false / null / numbers
sessions show read checkpoint score data from the wrong shape for SQLite-backed sessionsSession checkpoint tables showed -/- instead of real scoressrc/commands/sessions.js now reads nested cp.data.score with fallback support
node:sqlite printed ExperimentalWarning into normal CLI outputHuman-facing output was noisy and looked brokensrc/core/sessionStore.js filters only the SQLite experimental warning by default; set LEHRO_SHOW_EXPERIMENTAL_WARNINGS=1 to restore it
MCP schema still claimed baseBranch defaulted to mainDocs/schema contradicted the fixed branch auto-detection behaviorsrc/mcp/tools.js now describes baseBranch as optional and auto-detected
worktree.js still had a final hardcoded main fallbackIn unusual git states, orchestration could still violate ADR-0008src/orchestrator/worktree.js now uses current branch, then symbolic HEAD, then current commit SHA; outside git it returns per-worker errors
progressBar() could render invalid percentages for missing valuesDefensive UI issue if future score fields are absentsrc/core/ui.js clamps/non-numeric guards progress values
OWASP scanner joined user-provided file paths without root containmentA malicious --files ../../secret input could read outside the project root during scanningsrc/harness/owasp.js now resolves paths against cwd, refuses escapes, and emits an excessive-agency finding
OWASP scanner read entire filesLarge files could slow or exhaust lightweight scansScanner skips files over 1 MiB with a model-denial-of-service warning
Branch policy only blocked mainRepos using master were not protected by defaultsrc/harness/policy.js now defaults protected branches to main and master, configurable via protectedBranches
npm test script pointed at test/ in a way Node treated as a missing module in this sandboxTest script failed despite tests existingpackage.json now uses node --test "test/*.test.js" and includes test in package files

#Regression tests added

test/cli-audit.test.js covers the audit fixes:

  • --key=value parsing and boolean --dryRun=false
  • SQLite warning suppression in doctor
  • sessions show score display from nested checkpoint data
  • default branch protection for both main and master
  • OWASP scanner refusal of paths outside the project root

Run them with:

npm test

#Smoke-tested commands

node bin/lehrosol.js --version
node bin/lehrosol.js doctor
node bin/lehrosol.js loop run --prompt audit-smoke --agentAdapter local --dryRun=false --maxIterations=2 --owasp-scope llm
node bin/lehrosol.js sessions show --id <session-id>
node bin/lehrosol.js policy evaluate --branch master --hasTests --reviewCount 1 --owasp-scope llm

#Design principle reinforced

The audit reinforces the core LehroSol rule: if a behavior is documented, it must be executable exactly as documented. This is why parser correctness (--dryRun=false, -i), schema correctness (baseBranch auto-detect), and session display correctness (sessions show) were treated as product bugs, not cosmetic issues.

#Production-readiness audit — v1.0.0

This pass moved LehroSol CLI from alpha packaging toward a production-ready local developer tool.

#Production blockers fixed

AreaFindingFix
Release metadataPackage still shipped as 0.2.0-alpha.0Promoted package/core metadata to 1.0.0
Executable installbin/lehrosol.js was not executable on POSIXSet executable bit and added regression coverage
Package surfacenpm package included testsProduction files list now ships bin, src, docs, README.md, LICENSE only
Adapter configReal adapter setup was env/PATH-only and brittleAdded lehrosol config list/set/show/unset/doctor/wizard with saved local config
Local modelsLocal endpoints were not first-classAdded ollama, lmstudio, vllm, and localai adapters
CMUX-style operationWorktree/session orchestration existed but no thread commandAdded lehrosol threads list/run for multiple independent loop threads
MCP hardeningHTTP MCP lacked auth/readiness/body-limit hardeningAdded loopback default, optional bearer auth, /health, body cap, no-store/nosniff headers
MCP schemasAdapter schema was staleExpanded MCP adapter/schema coverage for config, threads, local models, NVIDIA, Qoder, Qwen, etc.
Secret outputMCP config save could echo secretsconfig_set now returns only { saved: true }; CLI output masks secrets

#Production regression suite

The suite now covers:

  • package version and executable bit
  • production command help (config, threads, tui)
  • MCP production version in initialize
  • MCP config/thread tools
  • MCP bearer-token enforcement and /health
  • saved NVIDIA config and masked secrets
  • local model adapters
  • CMUX-style thread state
  • TUI hotkeys and action routing
  • adapter ecosystem and tool registry safety

Final verification target: npm run check, npm test, npm run docs:build, and npm pack --dry-run.
