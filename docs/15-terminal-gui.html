15 · Terminal GUI — The HELIX Console (Immersive In-CLI Cockpit)

← 14 · Audit Report · Docs home · Next: 16 · Design System →

LehroSol ships a GUI that lives inside the terminal — not just the browser dashboard in gui/. lehrosol tui launches the HELIX Console: a live, animated, keyboard-driven agentic cockpit built on the HELIX design system. It is a CMUX-class control surface for loop + harness + orchestration, tuned for every skill stage (basic → intermediate → advanced), and it stays zero-dependency: pure Node.js + ANSI/Unicode, no blessed, ink, tui, or native UI libraries.

#What “immersive” means here

CapabilityHow it shows up
Animated brand bannerThe L E H R O S O L wordmark shimmers through the aurora gradient every frame
Live agent busA comet progress strip pulses across the header to signal an active, agentic surface
Live clock + spinnerThe header ticks in real time so the cockpit always feels alive
Focus navigationQuick Actions has a moving ❯ cursor you drive with ↑/↓ (or j/k)
Instant viewsd/a/s/p swap the whole surface to Doctor / Adapters / Sessions / Policy detail overlays
Stage switching1/2/3 reflow density between basic, intermediate, and advanced without leaving the cockpit
Gradient meters & sparklinesPolicy score, adapter availability, and health render as neon gauges, not plain text
Graceful fallbackPiped / CI / non-TTY contexts get a clean static paint with zero escape-code noise

#Run it

lehrosol tui                    # live immersive cockpit (auto-detects TTY)
lehrosol tui --mode advanced    # full control-plane density
lehrosol tui --static           # one-shot paint (pipes, CI, screenshots)
lehrosol tui --json             # machine-readable snapshot for agents/CI
lehrosol tui --ascii            # ASCII-only borders/glyphs for legacy consoles
lehrosol tui --no-anim          # disable motion, keep the layout

The live cockpit is also the destination of the interactive wizard (lehrosol -i → tui).

#How this differs from the web GUI

SurfaceUse it when
lehrosol tuiYou are in the terminal and want a live, dashboard-level cockpit without a browser
lehrosol tui --jsonAn agent, CI job, or script needs a machine-readable snapshot
lehrosol tui --staticYou want a single clean paint for a pipe, log, or screenshot
lehrosol gui + gui/ web appYou want a browser dashboard with clickable controls
lehrosol -iYou want a prompt-by-prompt wizard that then drops you into the cockpit

#Graceful degradation contract

  • Truecolor → 256 → 16 → plain: color depth is auto-detected (COLORTERM, TERM) and can be forced with --no-color / FORCE_COLOR.
  • Unicode → ASCII: --ascii (or LEHRO_ASCII=1) swaps box-drawing + glyphs for a legacy-safe set.
  • Motion → static: animations only run on an interactive TTY; CI, pipes, and --no-anim render a single frame.

#Full interactivity — every panel is live

The cockpit is fully keyboard-driven. Focus moves between panels and Enter executes the focused panel for real (actions run in the normal screen buffer so their output scrolls and is copy-pasteable, then you return to the cockpit).

KeyAction
Tab / ← → / h lMove focus between panels (Health, Adapters, Sessions, Policy, Orchestration, Quick Actions)
↑ ↓ / j kSelect a row inside the focused panel
EnterRun the focused panel
1 2 3Switch stage (basic / intermediate / advanced)
d a s pDetail overlays (doctor / adapters / sessions / policy)
rRefresh the snapshot
?Help · esc back · q quit

#What Enter does per panel

PanelEnter runs
System Healthfull doctor check
Agent Adaptersthe selected adapter live when configured; otherwise it shows exact setup instructions and does not pretend a smoke test was live
Sessionsinspect the selected session (or run a first loop if none)
Harness / Policyevaluate the policy/OWASP gate
Orchestrationspawn parallel git-worktree workers (asks how many)
Quick Actionsthe selected action: guided setup, health check, safe loop, sessions, policy, spawn, MCP, GUI

The Adapters overlay (a) shows every adapter's kind, endpoint/binary, readiness, and the active tool-calling toolset. See 08 · Agent Adapters for the adapter ecosystem and frontier tool calling.

#How actions run without freezing the UI

When you press Enter, the cockpit suspends: it stops the raw-mode key reader, leaves the alt-screen, runs the action against the real engine (runLoop, runDoctor, evaluatePolicy, spawnWorktree, runInitCommand), waits for a keypress, then re-enters the alt-screen and refreshes. This keeps rendering and blocking work cleanly separated.

#TUI hotkey audit upgrade

The cockpit now has an explicit, testable hotkey router instead of scattered ad-hoc key handling. This fixes the class of bugs where a visible shortcut looks clickable/actionable but does not execute.

#Audit findings

FindingImpactFix
The action path had a duplicated doctor variable declarationCould break the System Health → Enter action pathRemoved the duplicate declaration and covered the action route
Hotkeys were handled inline inside the live loopHard to test; shortcuts could regress silentlyAdded applyTuiHotkey() as a pure router and TUI_HOTKEY_CONTRACT
Numbered Quick Actions looked like buttons but number keys did not run themUsers could see 01, 02, 03 but pressing 1, 2, 3 only switched stagesWhen Quick Actions is focused, number keys now run the matching visible action
Enter was the only execute keySome terminals/users expect Space to activate focused buttonsSpace now also executes the focused panel
Shortcut coverage existed only visuallyNo automated guaranteeAdded test/tui-hotkeys.test.js with navigation, overlays, Enter/Space, number buttons, stage switching, refresh, and quit tests

#Tested contract

The following hotkeys are now regression-tested:

  • Tab, ←, →, h, l — panel focus
  • ↑, ↓, j, k — row selection
  • Enter, Space — execute the focused panel
  • 1, 2, 3 — stage switching, or numbered Quick Action buttons when that panel is focused
  • d, a, s, p, ?, esc — overlays and return
  • r — refresh
  • q, ctrl-c — quit

#Live adapter behavior

The Agent Adapters panel now follows a strict rule: live means live.

  • If the selected adapter is configured and launchable, pressing Enter or Space prompts for a real task and runs --dryRun=false.
  • If the adapter is not configured, the cockpit shows the setup command/env var and returns to the dashboard.
  • It no longer converts unconfigured adapters into local smoke tests while showing the selected adapter name.

This is especially important for NVIDIA NIM, Ollama, OpenCode, Qwen Code, and Qoder CLI because users need to know whether they are testing the real agent or only the harness.

KeyAction

The header bus line now shows preferred adapter, CLI/HTTP readiness counts, and tool-registry size. Advanced Quick Actions include Configure / run Grok and Set preferred adapter.

#Executable overlays and model control plane (v1.2.0)

The audit found that the command and thread overlays looked actionable but only displayed command hints. They are now real selection surfaces:

KeySurfaceInteraction
cCommand palette↑↓ select; Enter runs config doctor, model list/probe/run, sessions, or policy
mModel control planeSelect a curated Grok/local/hosted profile, show current model, or probe endpoint
tThreads planeList threads, launch a multi-thread run, or spawn worktrees
fAdapter panelToggle favorite
gAnywhereLaunch preferred adapter, then Grok, then first ready provider

Actions suspend raw-mode/alt-screen, execute in the normal terminal buffer, wait for acknowledgement, refresh state, and resume the cockpit.
